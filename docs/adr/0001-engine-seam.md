# Один движковый шов для всех внешних контрактов

Раньше знание о формате FluidAudio (командный контракт subprocess, JSON-схемы `wordTimings`/`segments`, релейблинг `S1..Sn`, политика языка) было размазано по четырём функциям `bin/transcribe` без единого теста. Решили собрать всё за один шов — `lib/engine.py` с портом `Engine.transcribe()`, тестируемым через fixtures реальных ответов движка.

Выбран порт с одним методом `transcribe()` (а не парные `asr`/`diarize`): двухпроходность FluidAudio — деталь реализации, облачный движок делает ASR+диаризацию одним вызовом. Движковые опции (model, diar_mode) живут в конструкторе адаптера, а не в порту. Другие дизайны (минимальный класс с `_run`-хуком, функция с merge внутри, протокол с capabilities) были рассмотрены и отвергнуты: либо не давали честного шва под облако, либо фиксировали топологию движка в интерфейсе.

Контракт порта: `words` и `segments` в формате, который ест `lib/merge.py` — merge намеренно не трогали. Парсинг JSON и разбор ошибок (`EngineError(stage)`) — внутри модуля; наружу не пробиваются `JSONDecodeError`/`KeyError`.

Дополнение (2026-08-01): порт отдаёт в результате и метаданные прогона — `Transcript.timings` (длительности проходов `asr_s`/`diar_s`, замеренные внутри шва) и `diar_mode` (фактически применённый режим диаризации, `None` если её не было). Правило «когда диаризация применяется» (`speakers != "off"`) живёт только в движке; потребитель не считает тайминги по порядку колбэков и не знает топологию проходов. `on_stage` — live-канал стадий для прогресса, и только.
